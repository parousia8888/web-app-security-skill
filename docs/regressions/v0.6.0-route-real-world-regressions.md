# v0.6.0 ordinary-project route regressions

These minimized guards protect six named correctness failures found during a purposive three-project review. They are not a representative accuracy benchmark.

| Regression | Origin | Failure | Protected contract | Remaining boundary | Guard |
|---|---|---|---|---|---|
| `nestjs-static-controller-options-path` | nestjs-boilerplate | A static @Controller({ path, version }) prefix was treated as dynamic and method routes were emitted at incorrect root paths. | Static NestJS controller option paths and path arrays contribute their declared prefix. | Computed option values remain dynamic and must not be guessed. | [test/nest-route-extractor.test.mjs](../../test/nest-route-extractor.test.mjs) |
| `nestjs-dynamic-controller-prefix-not-guessed` | nestjs-boilerplate | A dynamic controller prefix could be dropped while the method-only suffix was emitted as an apparently exact route. | An unresolved NestJS controller prefix produces path null instead of a guessed method-only path. | The analyzer does not evaluate arbitrary TypeScript expressions to recover dynamic decorator values. | [test/nest-route-extractor.test.mjs](../../test/nest-route-extractor.test.mjs) |
| `route-unrelated-import-failure-isolation` | uptime-kuma | An unrelated unresolved local import polluted the framework route coverage status. | Only route-relevant structural resolution failures can make Express route coverage incomplete. | A mount, router or handler relationship that is relevant and unresolved must still produce partial coverage. | [test/express-route-extractor.test.mjs](../../test/express-route-extractor.test.mjs) |
| `next-route-reexport-remains-incomplete` | vercel-chatbot | A route-handler re-export through a project alias could disappear without route-specific incomplete evidence. | Unresolved Next.js route-handler re-exports produce next_route_handler_export_unresolved and partial coverage. | Cross-module handler re-export resolution is not stable coverage in v0.6.0. | [test/next-app-route-extractor.test.mjs](../../test/next-app-route-extractor.test.mjs) |
| `route-coverage-reason-budget` | uptime-kuma | Framework reason counts could exceed the affected-input count exposed by report-v3 coverage. | Route coverage reason counts reconcile to affected input files instead of internal relationship-event volume. | A reason count is an affected-input count, not a number of missing routes. | [test/route-security-integration.test.mjs](../../test/route-security-integration.test.mjs) |
| `express-all-state-change-priority` | uptime-kuma | Express router.all was treated as read-only even though the handler accepts state-changing HTTP methods. | ALL is conservatively state-changing and receives state-change review reasons when controls are unresolved. | Static analysis does not know which HTTP methods a handler may reject internally. | [test/express-route-extractor.test.mjs](../../test/express-route-extractor.test.mjs) |
