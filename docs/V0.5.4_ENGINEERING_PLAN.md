## Objective

v0.5.4 corrects how the project describes and proves detector quality. The existing planted
fixtures verify that each built-in rule still follows its declared rule contract. They do not
measure production vulnerability precision or recall and must not be named or presented as
ground-truth accuracy evidence. A separate real-world regression corpus will turn already observed
failures into executable, reviewable gates without claiming statistical accuracy.

The release also strengthens the detector itself with a bounded Common Web Risk Detection Pack:
five built-in configuration or repository-fact rules, eight project-owned Opengrep same-file flow
rules and a `deep` profile that selects the existing built-in, Gitleaks, OSV-Scanner, Opengrep and
Checkov adapters without downloading them. The target stable contract becomes 25 built-in risk
rules, two evidence-integrity rules and 16 external-adapter risk rules: 43 stable rules total.

The earlier candidate work removes an unnecessary version pin from the main-branch first-trial
command, opens a lower-friction support channel and records the actual state of curated-list
submissions. Those completed changes remain part of the release.

## Non-goals

- No whole-program data-flow engine, MCP server, autonomous exploitation, Strix adapter or generic
  suppression engine.
- No production precision/recall percentage and no extrapolation from author-labelled fixtures.
- No broad refactor of evidence schemas or release machinery.
- No automatic download or installation of Gitleaks, OSV-Scanner, Opengrep or Checkov.
- No inference that an absent cookie flag is unsafe; new cookie rules require an explicit insecure
  value in a supported API or framework setting.
- No third-party active testing and no claim that same-file Opengrep flow proves reachability or
  exploitability.
- No automatic posting to promotional channels.
- No tag, GitHub Release, npm publication or `v1` movement without explicit approval.

## Evidence vocabulary

| Evidence set | Question answered | Allowed claim | Prohibited claim |
|---|---|---|---|
| Rule-contract conformance | Does each stable built-in rule still emit or stay quiet on its declared planted positive/negative neighbour, in the expected state? | All 27 declared planted contracts pass or fail reproducibly | Production precision, recall, exploitability or security coverage |
| Real-world regression corpus | Do previously observed correctness failures remain fixed under their minimal reproductions? | Named historical regressions are executable and currently pass | Representative prevalence, generic accuracy or third-party ground truth |
| Public-project case studies | What did a fixed-scope review observe and how were matches closed? | Project/commit-specific observations and closure evidence | A statistically representative benchmark |

## G7 - Capability scope and rule contracts

Built-in rules:

1. `tracked-sensitive-env-file`: use Git's index, without reading file contents, to report a
   sensitive `.env` filename that is currently tracked. `confirmed` applies only to the tracking
   fact. Credential presence, validity, history and artifact publication remain unproven.
2. `js-inline-session-secret`: detect non-placeholder string literals supplied to recognized
   Express Session, NextAuth/Auth.js and Nest JWT configuration properties. Redact literal values;
   remain `suspected` because deployment use and credential validity are not established.
3. `js-insecure-cookie-options`: detect explicit `httpOnly: false` or `secure: false` inside
   recognized JavaScript Cookie/Session API option objects. Missing properties are outside scope.
4. `python-insecure-session-cookie-settings`: detect explicit unsafe Django or Flask session/CSRF
   cookie settings. Missing settings and unrelated assignments are outside scope.
5. `python-csrf-protection-disabled`: detect explicit CSRF disabling in supported Django, Flask-WTF
   or Flask-SeaSurf settings/decorators. Route intent and compensating controls remain unproven.

Opengrep rules:

- JavaScript/TypeScript and Python same-file request-to-SQL-execution flows.
- JavaScript/TypeScript and Python same-file request-to-outbound-request flows (SSRF leads).
- JavaScript/TypeScript and Python same-file request-to-file-path flows (path traversal leads).
- JavaScript/TypeScript and Python same-file request-to-redirect flows (open-redirect leads).

Every Opengrep finding remains `suspected`. The evidence boundary must say that the project-owned
rule observed a same-file syntactic flow; it did not prove framework routing, validation bypass,
runtime reachability, exploitability or a deployed endpoint.
